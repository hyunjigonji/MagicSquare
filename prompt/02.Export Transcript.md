## Mom Test 워크북 — 각 항목 의미

### 1. 페르소나
**“누구에게”** 인터뷰했는지, **구체적인 한 사람**으로 적습니다.

- 좋음: “서울 거주, 30대, 스타트업 PM, 주 3회 이상 회의·의사결정 담당”
- 나쁨: “바쁜 직장인”, “IT에 관심 있는 사람”

Mom Test에서는 **가상의 평균 사용자**가 아니라, **실제로 만난 사람 1명** 기준이 낫습니다.

---

### 2. 인터뷰 답변 (과거 사실)
**미래 의견·가정이 아니라, 이미 일어난 일**만 적습니다.

| 쓰면 안 됨 | 써야 함 |
|-----------|---------|
| “~하면 좋을 것 같아요” | “지난달 X 때문에 Y를 3번 했어요” |
| “~가 필요해요” (솔루션) | “그때 ~ 때문에 ~시간/~원 들었어요” |
| “우리 앱 쓰면 ~” | “지금은 ~로 하고 있어요” |

예시 형식:
- “지난주 금요일, ~ 때문에 ~까지 ~했다.”
- “매월 ~할 때마다 ~를 ~분/시간 쓴다.”
- “~ 때문에 ~를 포기한 적이 있다.”

**검증 질문:** “그게 언제였어요?”, “그때 정확히 뭘 하셨어요?”, “그게 얼마나 자주/얼마나 비용이 들었어요?”

---

### 3. 표면 문제 (금지 — 솔루션 섞인 문장)
인터뷰에서 **솔루션·기능·제품 형태가 섞인** 표현입니다. Mom Test에서는 **문제 정의에 쓰지 않습니다.**

| 표면 문제 (금지) | 왜 금지인가 |
|-----------------|------------|
| “매직스퀘어 앱이 필요해요” | 제품 제안 |
| “알림 기능이 있으면 좋겠어요” | 기능 제안 |
| “AI로 자동화해줬으면” | 솔루션 가정 |
| “더 예쁜 UI가 필요해” | 구현 방식 |

이 칸은 **“이렇게 말하면 안 된다”**는 **안티패턴 기록용**으로 두는 경우가 많습니다.

---

### 4. 진짜 문제 (한 문장)
표면 문제에서 **솔루션을 전부 뺀 뒤**, **행동·비용·감정**이 드러나는 **한 문장**으로 정리합니다.

**공식:**  
`[누가] + [어떤 상황에서] + [무엇 때문에] + [구체적 손실/불편]`

| 표면 (금지) | 진짜 문제 (한 문장) |
|------------|---------------------|
| “퍼즐 앱이 필요해” | “출근 전 10분, 머리를 비우고 싶은데 지금 하는 건 재미가 금방 떨어진다.” |
| “대시보드가 필요해” | “매주 월요일, 팀 진행 상황을 확인하려고 4곳을 돌며 30분을 쓴다.” |
| “자동 리포트 기능” | “보고서 만들 때마다 같은 숫자를 다시 모으느라 밤늦게까지 일한다.” |

---

## MagicSquare에 적용하려면

워크스페이스에 제품 정의가 없어 **MagicSquare가 무엇인지**(퍼즐 앱, B2B 도구, 교육 제품 등)는 여기서 특정할 수 없습니다.

아래 중 하나라도 주시면, 위 템플릿에 맞춰 **초안을 같이 정리**해 드릴 수 있습니다.

1. **인터뷰 원문** (대화 메모, 녹취 요약)
2. **MagicSquare 한 줄 설명** (지금 생각 중인 아이디어)
3. **인터뷰 대상 1명** 프로필 (직업, 상황, 최근 관련 경험)

---

## 빠른 자가 점검 (Mom Test 3원칙)

1. **Compliment** — “좋은 아이디어네요”만 모았는가? → 과거 행동으로 다시 물어보기  
2. **Hypothetical** — “~하면 쓸 거예요?”만 있는가? → “마지막으로 그런 일이 언제였어요?”  
3. **Pitch** — 내가 제품을 설명했는가? → 제품 말 전에 **그들의 삶**만 듣기  

원하시면 인터뷰 메모를 붙여 주시면, **페르소나 / 과거 사실 / 표면 문제 / 진짜 문제** 네 칸을 구분해서 채워 드리겠습니다.

## 1. 마지막으로 틀렸을 때

**Q1** ✅  
마지막으로 4×4 마방진에서 **틀렸다고 확신한** 게 언제야? 그때 **뭘 보고** 틀렸다고 알았어?

**Q2** ❌  
빈칸 2개 채울 때 **자동 검증 기능** 있으면 실수 줄일 수 있을 것 같아?

→ **나쁜 이유:** 가정형·솔루션 제안. “~하면 좋겠다”는 의견만 나온다.  
→ **✅ 고친 버전:** 마지막으로 틀렸을 때, **행·열·대각선 중 뭐부터** 확인하다가 문제를 찾았어?

---

## 2. 검증/확인 비용

**Q3** ✅  
마지막 과제에서 **합이 34인지** 확인하는 데 **몇 분** 걸렸어? **손으로** 셌어, **코드로** 돌렸어?

**Q4** ❌  
`SquareValidator` 같은 **검증기** 만들면 확인 시간 **얼마나 줄어들** 것 같아?

→ **나쁜 이유:** 제품·클래스 이름 + 미래 추정. 본인의 **과거 행동·비용**이 아니다.  
→ **✅ 고친 버전:** 지난번에 **대각선 합** 확인할 때, **몇 줄/몇 칸**을 직접 더했어? **몇 분** 걸렸어?

---

## 3. 포기·중단 순간

**Q5** ✅  
4×4 마방진 풀다가 **중간에 멈춘** 적 있어? **그때까지** 뭘 했고, **뭐 때문에** 그날은 그만뒀어?

**Q6** ❌  
너무 어려우면 **힌트 버튼**이나 **단계별 가이드** 있으면 끝까지 풀 수 있을까?

→ **나쁜 이유:** 가정형(“~하면 ~할까?”) + 기능 제안. 실제 **포기 순간**을 듣지 못한다.  
→ **✅ 고친 버전:** 마지막으로 **포기하거나 과제를 미룬** 게 언제야? 그때 **어디까지** 채워놨어 — 빈칸 0개? 1개?

---

## 4. 같은 문제를 다시 풀 때

**Q7** ✅  
**같은 격자**를 두 번째 풀었던 적 있어? **첫 번째랑 두 번째**에 **뭐가 달랐어** — 시간, 확인 순서, 실수?

**Q8** ❌  
한 번 틀린 문제를 **다시 풀게 해 주는 연습 모드** 필요해?

→ **나쁜 이유:** “필요해?”는 본인 니즈가 아니라 **칭찬·동의**를 유도한다.  
→ **✅ 고친 버전:** 틀린 뒤 **같은 문제를 다시** 풀었을 때, **처음과 뭐부터** 달리 했어?

---

## 5. 다른 사람에게 설명/공유할 때

**Q9** ✅  
마지막으로 이 마방진 풀이를 **누구에게** 설명했어? 그때 **상대가 뭐라고** 해서 **네 설명을 고쳤**어?

**Q10** ❌  
친구한테 보여줄 **예쁜 격자 UI**나 **공유 링크** 있으면 설명하기 쉬울까?

→ **나쁜 이유:** UI·공유 기능 제안 + 가정형. **실제 설명 경험**의 마찰을 못 듣는다.  
→ **✅ 고친 버전:** 마지막으로 설명할 때, **행·열·대각선·중복** 중 **어디에서** 상대가 **막혔**어? 그때 **몇 분** 더 썼어?

# MagicSquare 세션 3 워크북

**입력 (Mom Test 결과)**

## 1) 주제 한 문장 (Mom Test 기반, 솔루션 최소화)

> **부분 마방진을 “다 맞았다”고 착각하기 전에, 행·열·대각선·중복을 한 번에 판정할 수 있는지 확인한다.**

*(솔루션 이름·UI·ECB 전체 구현은 넣지 않음 — **늦은 검토로 20분 낭비**라는 불편에 초점)*

## 2) R-G-I-O

| 항목 | 내용 |
|------|------|
| **Role** | 4×4 부분 마방진 과제를 푸는 **학습자** — 빈칸 2개(0)를 채운 뒤 스스로 맞는지 확인해야 함 |
| **Goal** | **채우는 중·직후**에 “행·열만 OK” 착각을 막고, **대각선 누락·숫자 중복**을 **제출 전**에 잡는다 |
| **Input** | 4×4 정수 격자 — 고정 칸 1~16, 빈칸 **0** 두 칸, 목표 합 **34** |
| **Output** | **판정 결과** — 통과 / 실패, 실패 시 **어떤 조건**인지 (행·열·대각선 합 ≠ 34, 1~16 중복·누락, 0 잔존 등) |

## 3) 성공 기준 3개 (Mom Test 증거와 연결)

| **SC1** | **두 대각선** 합(각 34)을 검사에 **반드시** 포함한다 — “대각선 **하나**”만 보는 실수 재현 불가 | *“대각선 하나를 빼먹어서 20분 날렸다”* |
| **SC2** | **1~16 중복·누락**을 검사에 포함한다 — 행·열만 맞아도 **겹침**은 별도 실패 | *“숫자가 겹쳤어”* / *“둘다야”* |
| **SC3** | “마지막 검토”가 아니라 **격자 입력 직후·한 번의 실행**으로 SC1+SC2 결과를 볼 수 있다 — 늦은 발견 비용 제거 | *“마지막에 검토하니”* + **20분** 낭비 |

### Rule — **실패 조건을 문장·상수로 고정**

Mom Test에서 드러난 **판정 규칙**만 명시한다.

| 규칙 ID | 내용 | 증거 연결 |
|---------|------|-----------|
| R1 | 각 **행** 합 = 34 (0 제외·미완은 별도) | 행만 맞다고 착각 |
| R2 | 각 **열** 합 = 34 | 동일 |
| R3 | **주대각선·부대각선** 합 = 34 (**둘 다**) | 대각선 하나 누락 |
| R4 | 1~16 **중복 없음**, **0은 최대 2칸** | 숫자 겹침 |
| R5 | (선택) 모든 칸 채움 — 0 없음 | “채운 뒤” 검토 전제 |

**산출물 예:** `rules.md` 또는 `ValidationRule` enum/상수 목록 — **코드 전에 문장으로 3개 이상**.

---

### Command — **한 번 실행하면 Rule 전체를 돌리는 진입점**

| 항목 | 내용 |
|------|------|
| **역할** | 학습자가 “마지막 검토” 대신 **즉시** 호출 |
| **형태** | CLI 한 줄 / 단일 함수 `validate(grid)` / REPL 명령 `check` |
| **동작** | 4×4 입력 → R1~R4 순서대로 검사 → **통과/실패 + 실패 Rule ID** 출력 |
| **하지 않음** | 솔버 호출, UI 렌더, 파일 저장 |

**산출물 예:** `validate` 진입점 + 실패 시 `"FAIL: R3 diagonal"` 수준 메시지.

---

### (Skill) — **검증 순서를 몸에 붙이는 최소 Skill**

*괄호 = 세션 시간 부족 시 Rule+Test Loop만 하고 Skill은 메모 수준.*

| Skill | 내용 | 왜 필요한가 |
|-------|------|-------------|
| **Checklist Skill** | 채운 직후 **행 → 열 → 대각선(2) → 1~16 중복** 순서 고정 | “행·열만 보고 넘어감” 재발 방지 |
| **ReadSkill** | 실패 메시지(R3/R4)를 보고 **어느 줄·어느 칸**을 다시 볼지 1줄로 적기 | 20분 헤매기 → 1~2분 수정 |

**산출물 예:** `CHECKLIST.md` 5줄 또는 주석 블록 — **자동화 전 수동 절차**도 Skill.

---

### Test Loop — **증거 기반 실패 격자로 Red → Green**

| 단계 | 내용 |
|------|------|
| **Red** | Mom Test에서 나온 **실패 유형** 3케이스 테스트 먼저 작성 |
| **Green** | Command가 Rule을 통과하도록 최소 구현 |
| **Refactor** | Rule ID·메시지 정리 (솔버/UI 추가 금지) |

**필수 테스트 케이스 (증거 매핑):**

| 테스트 | 격자 특성 | 기대 |
|--------|-----------|------|
| T1 | 행·열=34, **대각선 하나** ≠34 | FAIL R3 |
| T2 | 합은 맞지만 **숫자 중복** | FAIL R4 |
| T3 | T1+T2 **동시** (둘 다) | FAIL — **복수 Rule** 또는 첫 실패 명시 |

**루프 규칙:** 테스트 추가 → `validate` 실행 → 실패 메시지 확인 → **SC3** 만족할 때까지 반복.
